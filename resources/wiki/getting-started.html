🚀 Getting started

Two things for a Go UI program that should feel at home on a phone: material, pieces drawn the way Android’s own applications are (Material Design 3, with Material 3 Expressive’s newer pieces), and go-ui-apk, a tool that turns the program into an Android package.

Neither needs Java, Gradle or Android Studio. The program stays an ordinary Go main package that calls Go UI’s window.Run: on the desktop it opens a window, built for WebAssembly it draws in a web page, and on Android it is a shared library that Android’s own NativeActivity loads (Go Renderer’s android package).

Using the pieces

A program makes a material.Look in every frame, from the Go UI context and a colour scheme, and calls its pieces. Pieces that can be touched return true in the frame they are touched, as Go UI’s own controls do; the ones that keep something between frames (a pager, a carousel, a snackbar, a picker) take a small struct of the program’s.

dark := window.SystemPrefersDark()
scheme := material.System(dark) // the wallpaper's colours on Android 12 and later
context.Theme = scheme.Theme(dark)
look := material.New(context, scheme)

look.TopAppBar(material.TopBar{Title: "Lighthouses"})
if look.FilledButton("plus", "Add one") { … }
look.NavigationBar(places, &screen)

Sizes are Material’s: targets of at least 48 pixels, bars 64 and 80 pixels tall, 16-pixel text. A finger has no hover, so pieces change only while pressed. Each piece takes the name Go UI tells it apart by (its label, its icon or a name given); rows that repeat get a scope each with context.Push, as in Go UI. material.UseRoboto(), before the window opens, draws every text in Roboto, Android’s typeface.

Building against Go UI and Go Renderer

Go UI for Android builds against go-ui and go-renderer checked out beside it (replace in go.mod), until they publish versions with touches, insets, the wallpaper’s palettes and the Android window.

Then package it for a phone, and see every piece.
